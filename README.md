# ADEPS-test

## v0.5.4 — 毎回のLinear / ADEPS-test周波数比較

「拡散・音場スタジオ」で復元すると、同じ入力の **Linearと選択中の拡散推定**を振幅スペクトル誤差・Magnitude-Squared Coherenceの2図で比較できます。保存済みの中間段階、最終結果、履歴の選択、「過程を再生」に追従し、拡散のON/OFFで比較の2曲線が同一になることはありません。各周波数の値・CSV・ZIP内の記録も確認できます。

横軸は1 Hz〜20 kHz、計算データは16 kHz音声の非DCビン62.5 Hz〜8 kHzです。誤差軸は同一runの全保存段階で共通、Coherence軸は0〜1に固定します。[指標の式と原典・無音の扱い](docs/DIFFUSION_STUDIO.md)を明示しています。独自モデルの単一合成クリップでの比較であり、論文図の値・Param・Mismatched条件の再現ではありません。

## v0.5.3 — ノイズスケジュールと学習済み除去器の検証

「拡散・音場スタジオ」の「ノイズスケジュール」で、ステップごとのσを対数／通常目盛で表示します。現在の設定の予定と保存済みの実行ログを切り替え、各点・CSV・対応する保存済み3D音場と試聴対象を確認できます。終端0は対数軸と区別して示します。[操作と数値の意味](docs/DIFFUSION_STUDIO.md)

「学習済みノイズ除去器の検証」では、既存TinyDenoiserを新規の合成2,048ベクトル・10段階のσで評価し、未処理／単純ガウス縮小／学習済みのNRMSE・MSEを比較します。単純縮小から改善したのは3条件、最大改善は約0.033 dBで、残り7条件は悪化しました。モデルを再学習した更新ではありません。実音声・会場・論文同等の精度を示すものではなく、重みの識別と失敗例を含む[検証記録](public/models/tiny-denoiser-evaluation.json)を公開します。

復元後の「過程を再生」で中間推定→最終出力を連続試聴でき、3Dと数値が再生段階へ追従します。各短音の繰り返しは1・2・4回、全段階でゲインを揃えます。保存済み結果の聴き比べで、リアルタイム適応やオンライン学習ではありません。また、[データの出所](docs/MODEL_TRAINING.md)に論文のデータセットを使っていないことと、引用した手法・独自の生成データを明記しました。

## v0.5.2 — マイクアレイの3D表示

「拡散・音場スタジオ」で、復元前からマイクの本数・球面／リング・半径を3Dで確認できます。番号選択、XYZ座標、視点切替に対応し、現在の設定と保存した復元に使った配置を切り替えられます。「学習モデル比較」「マイク → Ambisonics」では計算結果に保存された配置を表示します。配置情報がない入力は補完しません。[操作と表示の意味](docs/DIFFUSION_STUDIO.md)

空間音響の数式と結果を、配置図・周波数特性・行列で確認する研究用テスト環境です。日本語／英語のUI、WebGLの配置表示、スピーカー再生系の合成実験、マイクからFOAへの線形符号化、録音済みインパルス応答（IR）の解析を備えています。

## v0.5.1：再生系の全帯域計算と学習データの出所

「目標からの誤差」は1 Hz〜20 kHzの256対数間隔点を合成モデルから計算します。CSV・複素行列・各周波数の評価も同じ範囲です。集計スコアは周波数点の変更に伴い変わるため、以前の80 Hz〜8 kHzの値との比較で手法の改善を判断しません。

「論文と実装の範囲」にモデル別の[学習データ・方法](docs/MODEL_TRAINING.md)を追加しました。再生系の線形計算には学習データを使わず、ニューラル推定用の2モデルは独自の合成データで学習しています。

## v0.5.0：拡散・音場スタジオ

4番目のタブ「拡散・音場スタジオ」で、仮想マイクの本数・配置・ノイズ、拡散のseed、観測への拘束を操作できます。同じ観測から別の復元候補を作り、途中のノイズ除去推定と最終出力を3D・ステレオ試聴・数値で比較し、全ステップの4ch FOA WAVを保存します。[スタジオを開く](https://keigoyoshida7.github.io/ADEPS-test/?tab=diffusion&v=0.5.0) · [操作と表示の詳細 / JP–EN](docs/DIFFUSION_STUDIO.md)

これは既存の独自小型拡散モデルによる合成音声実験です。3DはFOAの方向別RMSであり、会場内の音圧分布ではありません。既定0.35秒・16 kHz音声、非DC解析点62.5 Hz〜8 kHz。論文と同等の精度や線形推定からの改善は保証していません。ブラウザでは試聴操作時だけ音を再生します。Maxには書き出したWAVを手動で渡します。

## v0.4.0：独自学習モデルをON / OFFで比較する

**1,063,496パラメータの独自モデルを実際に学習し、「学習モデル比較」を追加しました。** マイクなしの合成実験と、Maxなどで作ったmono WAV → 仮想アレイ → OFF / ONのFOA WAV保存を使えます。実録音＋対応するマイク応答VのZIP入力も別に用意しています。リアルタイムの音声転送・推論ではありません。

- [新モデルの使い方・学習条件・全評価・論文との違い](docs/SPATIAL_MODEL.md)
- [Max実験パッチ](max/ADEPS_Experiment.maxpat)と[録音・A/Bの手順](max/README_EXPERIMENT.md)
- [固定した最終評価の記録](public/models/spatial-benchmark.json)と[学習済みモデルカード](public/models/spatial-v1.json)

独立した合成36シーンでは、調整済み線形法に対する平均NRMSE改善が0.74869 dBでした。既定線形との比較では30例改善・6例悪化です。別の合成WAV 3例では指標によって悪化もあり、**実音声の改善や論文超えは確認できていません。** 同じ入力のOFF / ON、周波数別結果、失敗例を保存して比較するための実験環境です。

## ブラウザで使う

[GitHub Pages](https://keigoyoshida7.github.io/ADEPS-test/)では、計算用のPython/WebAssemblyランタイムをブラウザに読み込みます。初回はランタイムと数値ライブラリの取得に時間がかかります。計算・入力ファイルの解析はブラウザ内で実行します。GitHub PagesはPythonサーバーを実行せず、Maxや音声デバイスへ接続しません。

1. 配置図で合成スピーカーの位置を確認します。
2. 再生実験で追加遅延や正則化を変え、再計算します。
3. 調整点と未使用点の誤差を比較します。調整点だけで改善していても、別の場所では悪化する場合があります。
4. 「学習モデル比較」では同じ入力のOFF / ONを比較します。音を聴いて比べる場合はmono WAVまたは録音ZIPを使い、FOAペアを保存して同じ外部デコーダーで再生します。
5. 「旧小型モデルの拡散推論」では合成データを実行し、線形との比較と反復履歴を確認できます。「合成WAV例を選ぶ」でFOA WAV書き出しも試せます。
6. マイク画面では、同一平面の配置にしてFOA復元のrank低下を確認できます。
7. IR画面では合成サンプルZIPを読み込んでから、自分で収録したIRの入力形式を確認できます。
8. JSON・CSVで計算条件と結果を保存できます。表示言語を切り替えても数値は変わりません。

周波数グラフは1 Hz〜20 kHzの対数軸で表示します。入力の有効データ範囲を併記し、データがない帯域には曲線を描きません。表示範囲を広げても、録音の帯域や解析データ自体は拡張しません。

旧小型モデルの拡散推論の「合成データで試す」は、**1 Hz〜20 kHz・対数間隔128点 × 16フレーム**を実際に生成・計算します（v0.3.2）。有限次数の合成音場での比較であり、全帯域の実測精度を示すものではありません。録音WAVの解析帯域は入力と解析サンプルレートに従います。

公開版の初期配置は、**12 × 9 × 4 mの合成室、12スピーカー、9調整点、6未使用点**です。特定施設の設定・測量値・測定音響は含みません。3D図は座標の表示で、測定された音圧分布ではありません。

## 自分のPCで動かす

Node.js 22.13以降とnpmを用意し、リポジトリのルートで実行します。

```sh
npm ci
npm run dev
```

表示されたローカルURLを開きます。これはブラウザのPython/WebAssemblyで計算するモードで、Pythonの手動インストールやローカル解析サーバーは不要です。ランタイムの初回取得にはネット接続が必要です。

### ローカルPython API・Maxを使う

Python 3.11以降も必要です。macOSでは **`ADEPS-test.command`** を開くと、依存ライブラリを準備し、ローカルPython APIとローカル接続用UIを起動します。初回はライブラリの取得を行います。ランチャーのターミナルでControl-Cを押すと、そのランチャーが起動したサーバーを終了します。MaxのDSP停止はMaxで行ってください。

手動で起動する場合は、まずPython環境を準備します。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

1つ目のターミナルで解析サーバーを起動します。

```sh
.venv/bin/python backend/server.py
```

2つ目のターミナルで、Python APIへ接続するUIを起動します。

```sh
npm run dev:local
```

`dev:local`はブラウザ内計算ではなく、起動済みのPython APIを使います。詳しくは[ローカル接続の手順](public/info/LOCAL_SETUP.md)と[Maxパッチの説明](max/README.md)を参照してください。

## 実装範囲

| 処理 | このプロジェクトで動く範囲 |
|---|---|
| 再生系 | 直接音＋6面の一次反射と機器誤差を合成し、周波数ごとのridge圧力マッチングを計算 |
| マイク → FOA | 既知の伝達行列Vによる線形符号化。合成デモと行列入力 |
| IR | 同期条件を保ったWAV群の応答、到達時刻の目安、任意の目標IRとの比較 |
| 学習モデル比較 v0.4 | 物理行列・観測の時間共分散で条件付けした1.063Mモデル。同じ入力のOFF / ON、mono WAVの仮想アレイ、実録音ZIP、FOAペア保存 |
| 旧小型モデルの拡散推論 v0.3 | 24,072パラメータの独自MLP、論文に基づく拡散推論式、線形との比較、反復履歴、短い録音のFOA WAV出力 |
| Maxの制御ブリッジ（既存） | ローカル版のみ。状態確認、1〜12ch選択、ミュート。DSPと音量はMaxで手動操作 |
| Max実験パッチ（追加） | mono音源作成・保存、raw 19ch録音、事前計算したFOAペアのA/B。Webへはファイルを手動受け渡し、デコーダーは外部 |

再生系の補正は、各周波数で `G = (HᴴH + λI)⁻¹HᴴT` を解く従来の線形処理です。ADEPSの拡散モデルではありません。各列の2ノルム制限は、同時入力時のピークやSPLを保証しません。書き出す複素行列から、実機用の因果FIRフィルターは生成していません。

複素NRMSEは `20 log10(誤差のノルム / 目標のノルム)`。小さいほど良く、0 dBは誤差の大きさが目標と同じ状態です。聴感評価・音圧・連続帯域の積分値ではありません。未使用点を見ながら条件を調整した後は、新しい点で最終評価してください。

マイクの合成デモは自由空間・無指向性・real ACN/N3D・`exp(+ikr·d)`という本試作の規約です。FOA順はW,Y,Z,Xです。論文で公表されていないSTFT条件や規約を再現したとは扱いません。参照のないデータでは復元品質の誤差・coherenceを出しません。録音ZIPのニューラル経路では、参照がある場合に時間信号のSI-SDRを算出します。ILD・ICの評価は未実装です。

## IRの入力

ZIP直下に`manifest.json`を置き、`schema: adeps-test-ir-bundle/1`と`speaker_files`を指定します。1つのWAVが1スピーカー、各WAVのチャンネルが測定点です。[テンプレート](public/examples/manifest-template.json)を参照してください。

- 全WAVでサンプルレート・長さ・チャンネル数・時刻原点・レベル基準を合わせます。個別の自動時間合わせは行いません。
- `target_files`は任意。目標がなければ応答と到達の診断だけを表示します。
- 目標がある場合、`training_indices`と`heldout_indices`に重複しない0始まりの点番号を指定します。
- 入力上限はZIP 32 MB、展開後100 MB、観測IR合計300万サンプル、32スピーカー、64測定点です。
- 10%相対ピーク閾値の到達時刻は目安です。収録・スイープ生成・逆畳み込み・厳密な直接音同定は実行しません。

## 開発・検証・公開

```sh
npm run build
npm run test:max
```

Python数値テストは、依存ライブラリを入れた環境で実行します。

```sh
PYTHONPATH=backend .venv/bin/python -m unittest discover -s tests -v
```

GitHub Pagesへは静的ビルドを配信します。ブラウザ版にローカルAPIやUDPブリッジを公開する構成ではありません。公開画面とローカル版の違い、検証対象は[検証範囲](docs/VALIDATION.md)に記載しています。

画面はモノクロと游明朝体を基本にしています。フォントファイルは同梱せず、端末にない場合は明朝系の代替書体で表示します。
