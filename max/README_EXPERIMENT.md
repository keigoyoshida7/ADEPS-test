# ADEPS-test / Max 実験パッチ

`ADEPS_Experiment.maxpat` を Max 9 で開きます。追加パッケージや Node for Max は使いません。音声はWAVファイルを手動で受け渡します。**このパッチからWebへの音声ストリーミング、リアルタイム推論、AFC／Sound xR設定変更は行いません。** 既存の `ADEPS_Test_Channel.maxpat` はチャンネル選択用の制御ブリッジであり、別の役割です。

## まずマイクなしで試す

1. MaxのAudio Statusでサンプルレートを確認します。新しい実験用には48 kHzを推奨しますが、パッチは自動変更しません。
2. 論理出力 `0`、`OUTPUT GAIN 0` のまま、SOURCEで `Mono WAV` を選び、短い**モノラルの声**を開きます。ステレオファイルを開くと最初のチャンネルだけを使用するため、比較用にはあらかじめmono化してください。
3. DSPを手動でオンにします。出力0とGAIN 0では、このパッチの物理出力は閉じています。
4. 「元音源 / mono 保存先…」で新しい `.wav` を選び、「録音 START」→`SOURCE RUN` の順に押します。終了後「停止 / CLOSE」を押します。
5. 保存したmono WAVをWebの実験ページで読み込み、仮想アレイへ入力します。シミュレーションでは音源方向からFOA参照を構成できるので、OFF/ONの誤差と音を比較できます。これは現場の録音を再現した検証ではありません。

元のmono WAVがすでにある場合は、Maxで再録音せず、そのファイルを直接Webへ読み込んでも構いません。Maxでの保存信号は出力GAINより前です。会場の出音を0にしても保存できます。正規化範囲を超えるサンプルは `clip~ -1. 1.` で制限されるため、元ファイルを基準にする場合には再録音との差も考慮してください。

パッチを開くだけでは生成・録音・再生を開始しません。別パッチがすでにDSPをオンにしていても、本パッチの音源選択・RUN・出力・GAINは0です。DSPはMax全体で共有されます。

## 何の音を使うか

| 音 | 確認すること | 適用範囲 |
|---|---|---|
| 1人の短い発話 | 音源方向・雑音・推定前後の歪み | まず使う入力。文や話者を学習用と分ける |
| 別の2人の発話 | 同時に違う方向から来る音を保持できるか | 仮想2音源、または実際に異なる位置の2人を19ch収録。パッチの会場出力は1音源だけ |
| monoの楽器・音楽 | 声以外への一般化、アタックや残響の変化 | 論文の評価条件と異なる部分を明記する |
| ピンクノイズ | 各出力の到達、録音の欠落・クリップ、概略帯域 | 独立した経路確認。推論結果を校正の正解にしない |
| 20 Hz–20 kHz log sweep | 帯域、遅延、反射を調べるための素材 | 8秒、前後20msのフェード。逆フィルタやIR推定はこのパッチに未実装 |
| 100ms pink burst | 到達順、残響の尾、録音開始の余白 | 10ms立ち上がり＋80ms保持＋10ms立ち下がり |

SweepとburstはSOURCEで選択し、RUNをオンにしてから「Sweep / burstを1回」を押します。自動反復しません。Sweepは1 Hzから出力しません。Webの1 Hz–20 kHzのグラフ表示や計算範囲は、実機をその帯域で鳴らせること・推定精度がその全域で保証されることを意味しません。

## 実機で収録する

1. 接続した音声ドライバの入力1–19が、マイクの**変換前の19ch**に一対一で対応しているか確認します。この配線はZM-1の19ch収録を想定しており、4chのB-format、ViRealの60/64chへそのまま適用できません。個体の世代・チャンネル順と応答データの対応も確認します。
2. マイクの中心位置・高さ・正面と、音源の位置・高さ・向き・出力IDを記録します。位置やチャンネル対応をパッチが推定することはありません。
3. 「マイク / raw 19ch 保存先…」で新しいWAVを選びます。元音源も保存するなら双方で別々の保存先を選び、「両方の録音 START」を押します。経過ms表示が双方で動くことを確認します。保存先を選ばなかった側は開始しません。I/OエラーはMax Consoleも確認します。
4. 声などを1つの会場スピーカーから出す場合、論理出力1–12を選び、SOURCE RUNをオンにしてから `OUTPUT GAIN` を徐々に上げます。上限0.030はデジタル振幅の倍率で、会場での音圧上限ではありません。出力を変更するとGAINは0に戻ります。
5. 録音を先に開始し、発音の前後に余白を残します。終了時は `STOP ALL / MUTE`。録音を閉じた後は、次の収録ごとに保存先を選び直します。

19chは1つの `sfrecord~ 19` へ無加工で入り、同じ録音処理で保存されます。ただし、USBマイクと再生用Danteデバイスが別クロックの場合、共通イベントで録音を開始しても実際の入出力時刻やドリフトは一致しません。集約デバイスの構成、サンプルレート、レイテンシー、必要な時間合わせは別途確認します。

**元mono音源は、室内での反射を含む正しいFOA録音ではありません。** 実録音でSI-SDRなどを正解比較するには、別途妥当なFOA参照と時間・振幅合わせが必要です。参照がない場合は入力整合性・再現性・聴感を報告し、正解に対する改善量を捏造しません。

デバイスの選択、Dante subscription、スピーカーの保護設定は手動確認です。Maxの論理出力1–12と施設のDante番号を混同しないでください。マイクは部屋の音を録るために使います。応答データのないアレイを現場の反射込みで録っただけでは、反射を除いたマイク応答の代わりにはなりません。

## Webの結果をMaxでON/OFF比較する

1. Webから、**同じ試行**の `Linear` と `Enhanced` のFOA 4ch WAVを書き出します。チャンネルは **ACN/SN3D、W,Y,Z,X**。同じサンプルレート、長さ、時刻原点、共通の書き出しGAINのペアを使います。別々のピーク正規化は比較の公平性を失わせます。
2. OFF側へLinear、ON側へEnhancedを開きます。新規ファイルを開く操作はA/Bの再生を止め、FOA BUS GAINを0にします。ファイルの仕様は自動検証しないので、生成元の情報で照合してください。
3. 同じ外部FOAデコーダーの入力へ、`receive~ adeps-experiment.W`、`.Y`、`.Z`、`.X` を接続します。このパッチ自身にはFOAデコーダーがありません。**4chを4つのスピーカーへ直接つなげないでください。** 受信側の規約がN3D/FuMaの場合は変換が必要です。
4. 「A+B 同時 START」を押し、FOA BUS GAINを徐々に上げます。両方は同じ制御イベントで先頭から再生されます。厳密な開始位置は実際のMax設定で確認してください。音源のピークや先頭無音が異なるペアは使わないでください。
5. チェックを外すとOFF=Linear、入れるとON=Enhanced。再生位置をリセットせず20msで重みを切り替えます。長さが違うと先に終了した側に合わせて両方を停止します。終了時は「A+B STOP」または「STOP ALL / MUTE」。

これは事前に計算した結果の比較です。トグルがモデルの計算をリアルタイムでON/OFFするわけではありません。bus名は固定なので、このパッチを同時に複数開かず、同名の受信先を確認してください。

## 再生成と検証

```sh
node build-experiment-patch.js
node --test experiment.test.js
```

生成用JavaScriptは開発用で、Maxでの利用時には不要です。検証範囲と未検証項目は `EXPERIMENT_VALIDATION.md` を参照してください。
